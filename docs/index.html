Five-minute research update

Evidence-Aware RAG for Cardiology Questions

A research prototype comparing ordinary fixed top-k retrieval with a method that checks evidence, retries retrieval once when useful, and abstains when support remains insufficient.

Project at a glance

Research prototypeEducational QA, not clinical diagnosis or treatment.
Two retrieval approachesFixed top-k baseline and evidence-aware adaptive retrieval.
Evaluation is nextNo corpus-backed benchmark results have been produced yet.

What is implemented

  • Local source manifest validation, text/Markdown ingestion, stable chunking, and provenance metadata.
  • Deterministic lexical retrieval and optional dense retrieval using sentence-transformer embeddings.
  • Fixed top-k RAG baseline; adaptive query intent/expansion, evidence sufficiency gate, one bounded retry, and abstention.
  • Source citation formatting and structural validation, extractive fallback, and optional Ollama-compatible generation through environment configuration.
  • Shared evaluation runner, four system variants (baseline, EA-RAG, and two ablations), machine-readable run artifacts, and a minimal Streamlit interface.
  • Unit test suite: latest recorded run passed 15 tests. No live Ollama request or benchmark run has been made.

Core code is under src/cardio_rag/; setup and usage are in README.md; remaining research work is tracked in docs/TODO.md.

Data status and decision

A MedQA-USMLE copy is present locally with US train/dev/test questions and 18 English textbook extracts. The supplied English textbook corpus has been ingested into 27,348 local chunks. Separate keyword candidate files were generated from the 1,272-item dev split (325 candidates) and 1,273-item test split (349 candidates). The filter is overinclusive and requires manual review. This is an exam-style question set, not consumer cardiology FAQ data.

Two LiveQA-related files are also present in data/evaluation/: a qrels file and a CSV mapping answer IDs to answer text.

What the qrels mean: each row maps a query ID to a graded judgment and an answer ID (for example, 1 2-Related ANSWER_ID). These are retrieval relevance labels, not the query text or a source corpus. The matching LiveQA test questions are still needed.
Use restriction to resolve: the official MedQuAD README says answer text was removed from three MedlinePlus subsets, including A.D.A.M., to respect copyright. The separate CSV shown in the project contains ADAM_... answer text. Do not ingest or redistribute that text as demo source material unless permission is confirmed. The repository's overall CC BY notice does not by itself establish permission for material explicitly excluded in the README.

Recommended route: use separate MedQA-USMLE dev and test question splits for a secondary exam-style evaluation after manual topic review. Its paper describes the textbook corpus as released under a research-use-only agreement; confirm and follow the terms applicable to this copy. Source text and derived chunks are local and Git-ignored. The matching LiveQA questions are still needed if using its qrels.

MedlinePlus identifies health-topic summaries as public domain and separately identifies A.D.A.M. Medical Encyclopedia content as copyrighted: MedlinePlus content policy. MedQuAD documents its exclusions, qrels format, citation, and CC BY 4.0 statement in the official repository README.

Plan: turn the prototype into a reproducible experiment

Lock the data
Confirm source rights; assemble 5–10 permitted cardiology education documents; record publisher, URL, date, and terms.
Build evaluation sets
Create a small development set and a separately held-out test set; include answer notes and relevant source/chunk labels where supportable.
Run comparable systems
Ingest once; run lexical and dense retrieval, baseline and EA-RAG variants on the same questions; tune thresholds only on development data.
Review and report
Manually assess evidence support, citations, abstentions, and errors; report measured metrics, limitations, configuration, and data provenance.

Research boundaries

  • Educational prototype only; not clinically validated and not for diagnosis or treatment decisions.
  • No real patient records or identifiable health information.
  • Retrieval scores are not calibrated confidence. Structural citation checks do not prove that an answer is supported.
  • Keep benchmark test questions out of prompt, threshold, and retrieval tuning.
  • Do not present planned experiments as completed results.
